## 바꾸지 않을 계약
1. 현재 생산 기능을 삭제하거나 기존 gate를 낮춰 "성공"으로 만들지 않는다. 현존 `final_video_qa.py`, `visual_qa.py`, `entertainment_qa.py`, `rumble_native_shard_qa.py`, `episode2_film.py` 유지. 기존 원칙: 완성된 MP4가 나와도 **인간의 영상 검토 전에는 게시 불가**.
2. **품질 > 속도**. Render Cycles 32spp, 1080×1920, 원본 30fps 900프레임, 소스 해시·라이선스 보존. 최적화는 통제 A/B/A 테스트와 화질 동등성을 증명한 뒤에만. 대량 3D 재렌더는 3~9장의 실제 네이티브 샘플 합격 후.
3. 자동 PR 병합·자동 YouTube 업로드·자동 유료 API 호출·유료 runner/GPU 업그레이드 금지. 영상 업로드는 사용자가 직접 한다. 리뷰 링크에는 항상 `INTERNAL REVIEW`와 `NOT UPLOAD READY`를 명시.
4. 이미 사용 중인 오픈소스 CC0 소스 및 검증된 공개 에셋 재사용 우선. 출처·라이선스·실제 장면 적합성 확인. 다른 저장소의 코드를 가져오면 라이선스/테스트/호환성 검증.
5. 영어 쇼츠 나레이션은 자연스러운 영어, 설명이 아닌 **현상을 먼저 보여주는 이야기 구조**. 대사-실제 화면 불일치·허위 시각 증거·조기 오답 노출 금지. 연구된 사실과 시각적 비유를 구분.
6. 카메라는 기본적으로 샷 안에서 고정하되 실제 물체 변화와 편집으로 화면 변화를 만든다. 물리 접촉을 **과장/위조**한 가짜 시뮬레이션은 합격 불가.
7. 성공한 코드가 아니라 **실제 업로드 가능한 1편**을 최종 산출 단위로 삼는다. 조회수·잔존율은 실제 게시 후 데이터로만 평가하고 업로드하지 않은 영상의 수익·Retention을 추정하지 않는다.

## 매주 품질 성적표: 측정 가능한 것과 불가능한 것
`python -m shorts_studio.quality_program --out build/quality-program/week01.json`은 원본 최종 검수 데이터가 없으면 **NOT_MEASURED**를 출력한다.
완료된 정품 `film_validation.json`이 있을 때 `--film-validation <파일>`을 지정하면 기존 엄격한 체크를 통과했는지, 900개의 개별 실제 프레임 증거, 의미·시각 QA 결과, per-frame 50/95백분위 렌더시간, 총 CPU 계산시간, 인코딩 시간, 무음 총량/최댓값을 묶는다. **총 CPU 렌더시간을 실제 경과시간이나 ETA로 바꾸어 주장하지 않는다.**
사람 평가가 없으면 `NOT_REVIEWED`다. 별도 검수 JSON에는 `reviewer`, `evidence`, `notes`, 여섯 개 `ratings`(0–3 정수) 필요:
- `subject_legibility`: 첫 1~3초 현상과 대상 이해
- `visual_realism`: 실사성/재질/광원/모델 품질
- `physical_contact`: 장면 속 물리적 접촉과 기술적 사실
- `motion_variety`: 볼거리 변화, 단조로움 및 카메라 안정성
- `voice_naturalness`: 비로봇 음색, 호흡·무음·발음
- `narrative_retention`: 훅→의문→증거→반전/해결
0=큰 결함, 1=미흡, 2=검토 가능한 수준, 3=매우 우수. 항목 2 미만은 `NEEDS_REVISION`; 모두 2 이상이어도 단지 `REVIEWED`일 뿐 **자동 업로드 승인 아님**. 영상 본문과 정당한 근거를 직접 본 사람만 평가한다.
유튜브 지표: `stayed to watch`, 3초 진입, 첫 5초/끝 시청 유지, 평균 시청, 반복·구독 전환은 사용자가 실제 업로드한 뒤에만 기록. 이전 영상과 동일한 게시 시간대/길이·주제 요소를 고려하여 비교하되 소표본 변동을 절대적 성공이라 주장하지 않는다. 숫자 임계값을 임의로 CI PASS에 넣지 않는다.

## 주간 운영 루프
1. 실제 렌더/음성/유튜브 근거 수집 → 측정 누락은 `NOT_MEASURED`.
2. 불합격 장면 1~3개만 골라 **원인 → 실패 재현 테스트 → 최소 변경 → 전체 회귀**.
3. 전체 900프레임 대신 소수 실제 Cycles32 샘플 A/B → 개선 장면 인간 검수.
4. 정확한 Renderer SHA 고정, 실본이 모이면 900프레임 렌더 → 원본 assembler+최종 semantic/video QA.
5. 새 성적표/스크린샷/음성 A/B 결과를 Draft PR에 기록 → QA 실패 시 폐기/롤백.
6. 전체 제작이 가능한 상태에서만 사용자가 직접 업로드. 이후 실제 게시 데이터로 학습하고 다음 주 백로그를 조정.

**중간 중단 조건:** 렌더 격차가 커짐, 음성이 더 로봇 같아짐, 영상이 사실관계를 오해하게 함, 자막 겹침, 치명적 CI 실패, 무료 한도 사용 폭증. 해당 변경은 "더 신기해 보인다"는 이유로 통과시키지 않는다.
